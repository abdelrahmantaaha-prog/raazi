Three things worth knowing before we begin.

Raazi is the most sophisticated thing you have built. Not the biggest — Knight Run is a third bigger — but the one with the most genuinely hard problems solved properly: a durable job queue, a taxonomy of API failures, entity resolution, and a verification pass that catches a class of error nothing structural can see. This page walks the spine: the queue, the error taxonomy, the key ring, the entry pipeline, and the ledger.

Chapter 1

What this thing actually is

A machine that reads your library once and writes an encyclopedia from it, where every sentence traces back to a quote at a page number.

Feed it books, papers, articles and recordings. It finds every person, organisation, institution, event and place, and writes an entry for each. Add another source next month and the existing entries revise themselves, and tell you what changed.

part 1

A Next.js app on :5400

Pages and API routes, served from your own machine. Started by Raazi.exe — a 15 KB C# launcher that sits in the tray, so the clinic-style “never see a terminal” rule applies here too.

the source of truth

SQLite, 18 tables

Sources, chunks, entities, mentions, relations, events, entries, revisions, contradictions — plus runs and tasks, which are the queue. Your library and the database never leave the machine.

part 3

A background worker

A loop that claims one task at a time, calls a model, and writes the result. Ingesting a book is hundreds of calls over hours — Chapter 3 is what happens when one of them fails.

part 4

Five providers, one router

Gemini, Groq, Cerebras, OpenRouter, Mistral, and anything speaking the OpenAI API. Chapter 5 is the three routing rules that hold whatever you configure.

The sentence that explains the whole design

Raazi is a long-running job on free-tier quotas. A book is hundreds of calls across hours or days, on keys that will run out, on a machine that will be closed. Nearly every unusual thing in this codebase — the durable queue, the error taxonomy, the key ring, the hourly backoff, the parked-run timer — exists because that sentence is true.

Compare it with the other AI apps in your folder. Loqma makes one call and shows you the answer. Raazi makes eight hundred and has to survive all of them.

Check yourself: you kill the process halfway through a 400-page book. How much work is lost?

The shape to notice

Everything converges on chunks — roughly 3,500-token windows split on paragraph boundaries, each carrying the page, chapter or timecode a citation will point at. Parsing, OCR, extraction, entries and citations are all operations on chunks.

When a system has one central unit like that, learning it is mostly learning that unit. Find the chunk in the schema and the rest of the pipeline reads as things done to it.

Chapter 3

A queue that survives being killed

Every unit of work is a row. That one decision is what makes a three-day job resumable.

The tempting implementation is an array of work in memory and a loop over it. It works beautifully until the laptop sleeps, and then eight hours of a book are gone with no record of how far it got.

So the queue is a table, and claiming from it has to be safe against two workers racing.

The two rules that make this work

Claim atomically. One UPDATE … RETURNING selects and marks in a single statement. Doing the select and the update separately leaves a window where two workers grab the same task — and the comment on line 42 says exactly that.

Finish transactionally. Handlers must write their own results and mark the task done inside one transaction. Either both land or neither does, so a kill can never leave results written with the task still pending — which would duplicate them on restart.

Together those give you: kill the process mid-book and lose at most one task. On restart, anything left running goes back in the queue.

Priority, and why strict order is wrong

First-come-first-served is correct for a pipeline and wrong for a person. A question typed into Ask would sit behind five hundred re-extractions — twenty minutes — while you watch. So work is ordered by who is waiting on it: 0 for anything you are looking at right now, 1 for the reading pipeline nobody is watching, 2 for decoration.

Within a band it stays first-come, so nothing starves and a long ingest still runs in the order it was queued.

Check yourself: the process dies after a handler writes 40 mentions but before the task is marked done. What is duplicated on restart?
Chapter 4

The error taxonomy that makes resuming possible

Six dispositions, and the distinction between two of them is worth hours of your life.

The file opens by naming it: “a 429 because you sent 11 requests in a minute is a two-second problem, and a 429 because you burned the day's free quota is a tomorrow problem.” Treat them the same and you either waste hours of backoff or hammer a dead key all day.

And the classification itself, which is where the hard-won judgement lives.

Asymmetric costs

Read lines 191–194 twice. A bare 429 with no quota metadata is assumed to be a short window, not a spent day. The reasoning is about which way it is cheap to be wrong:

Guess “spent for the day” over a per-minute burst → you park a key for eighteen hours and waste most of a free tier. Guess “short window” over a genuinely spent day → you waste one call.

When two errors have wildly different costs, the right default is not the most likely one — it is the cheap one. That principle is worth more than the specific rule.

Chapter 5

The key ring, and three rules the router will not bend

Free tiers are per key, so three keys are three times the throughput — and the interesting code is about when a refused key comes back.

An hour, not a day

A refused key is set aside for an hour, and the wait only doubles — to a cap of eight hours — if it is refused again on its first call back. Any single successful call resets it entirely.

The cap is chosen with the arithmetic stated: “eight hours is long enough that a truly spent day costs three wasted calls.” Three wasted calls against not losing most of a free tier to a misdiagnosed burst. That is the trade, and it is written down where the constant is.

Who answers which question

Reading passages is around 88% of all tokens and needs nothing but text in and JSON out — so sending it to a cheaper provider is what makes a Gemini quota last. But three rules hold whatever you configure.

The Arabic rule, and why it is absolute

The cheaper providers are appreciably weaker on Arabic, and — this is the phrase that matters — “a name they miss is lost silently rather than slowly.”

A slow failure you notice and wait out. A silent one produces a pedia that is simply missing people, with nothing anywhere to indicate it. So non-Latin sources override your routing, and where no language is declared — PDFs, pasted text — the router reads the passage itself and decides.

That rule and the capability rule are the two test-routing.mjs exists to defend, because both fail invisibly.

Check yourself: a PDF declares no language. How much non-Latin text makes the router treat it as non-Latin?
Chapter 6

Entries are derived, not authored

An entry is a function of the evidence, and the evidence grows. One hash makes that mechanical.

Two rules, deliberately separate

A new entry is only written once an entity clears the mention threshold, so the hundreds of names a book produces do not each cost a call.

An entry that already exists is always brought back into line with its evidence, however small the entity — because “a stale entry contradicts the sources it cites, which is the one thing this tool must not do.”

Conflating those two was a bug, and the comment at the top of lib/entries.ts says so. They look like the same question and are not.

The bug that a matching hash concealed

Here is a failure that would be very hard to find by looking. The US entry had 146 quotes behind it and cited 52 of them — 36%. Entities with a dozen quotes were at 100%.

The difference is not judgement, it is room: asked to turn 146 passages into one entry in a single response, a model compresses, and what it compresses away is most of the evidence. And nothing ever revisited it, because built_from_hash recorded all 146 as accounted for. The entry was, by the system's own definition, perfectly fresh.

The fix is two-part: write a large entity over several passes, each folding in a batch of evidence the entry does not yet cite; and add a second staleness definition — undercovered — so an entry citing a fraction of its evidence is rewritten even though its hash matches.

Notice that the coverage count is done in SQL rather than by parsing every body in JavaScript, because it runs on every idle sweep. A correctness check that is too slow to run often is a correctness check that does not run.

Check yourself: an entry was written from all its evidence but cites a third of it. Is it stale?
Chapter 7

The citation that lies

The best comment in your entire folder, and the failure it describes is the one this application exists to prevent.

An audit of the library found every entity at 100% coverage with no dead citations. Inside one of them:

From lib/pipeline/verify.ts

Al Saud is the ruling dynasty of Saudi Arabia [[m:36243]] [[m:36917]] …

…where the cited passages are about Abdullah Sulaiman not being a member of it.

The sentence is true. Its truth comes from the model's own knowledge of the world rather than from the books — “which is the single thing this application exists to prevent, wearing a citation so it cannot be seen.”

And no structural check can catch it. The marker is real, the mention exists, it belongs to this entity, the sentence is cited. Every automated integrity test passes. Only reading the quote and the sentence together settles it.

The prompt is the design

Three verdicts, and the definitions do the work. “Overstated” gets concrete examples — a passage saying an arrangement “could” do something does not support a sentence saying it did. And “unsupported” explicitly names the hard case: “sentences that are perfectly true in the world but simply absent from the evidence — that is the most important case here, and the easiest to wave through, because a false sentence looks wrong while a true unsourced one looks fine.”

That last clause is the whole insight. A checker looking for errors will not find these, because they are not errors. It has to be looking for something else.

Report, do not edit

The pass flags and does not rewrite, for a stated reason: “a rewrite would quietly bury the disagreement, and what you want to see is the disagreement.” Entries stay exactly as written and the flags sit beside them.

And when the entry is next regenerated, the verdicts ride along — sentence by sentence, with the verifier's note on what the passages actually say. The instruction is to investigate, not to obey: a flag can be wrong, and the evidence is in front of the writer to check. What is forbidden is repeating the claim unexamined.

Check yourself: a sentence is dull, obvious, and exactly what its quotes say. What verdict should it get?
Chapter 8

The one place you overrule the model

And the most carefully-worded claim in the codebase, because “Raazi learns from your corrections” is the kind of sentence that quietly means nothing.

Everything else in Raazi decides what counts as evidence by asking a model. Discarding a quote is where you say no — and the design follows from what makes that worth doing at all: “a rejection you have to repeat is not a judgement, it is a chore.”

Two mechanisms, and only one is a guarantee

It BLOCKS. The quote never returns to that subject's evidence — not on re-extraction, not when Enhance takes a second look, not when the zero-token sweep matches the name again. A deterministic rule, enforced in SQL and at both places mentions are written. It holds whatever any model decides later.

It TEACHES. Your reason goes back into the prompts that produced the mistake, as a standing correction in your own words. This is a nudge, not a guarantee — a model told “you have twice attributed the son's quotes to the father here” will usually not do it a third time, and may.

Stating that split plainly is the point. What is true here is that the same passage cannot come back, and that the model is told why it was wrong. Those are different strengths of claim and the file refuses to blur them.

Making the block actually hold

Re-extraction writes new rows for old quotes, and those rows arrive without the marks their predecessors carried. So there are two enforcement points: an insert-time check against an index built once per pass, and reapplyDiscards, which re-applies the whole ledger to whatever is currently in the mentions table.

The detail worth stealing is where the comparison happens.

And nothing is deleted. A discarded mention keeps its row, stays readable under the entry marked with your reason, and can be restored — “because the only thing worse than evidence you have to reject by hand is evidence that disappears when you do.”

Check yourself: a quote is re-extracted with its line breaks folded differently. Does the block still catch it?
Chapter 9

The cheapest call is the one you do not make

A born-digital PDF becomes Markdown locally, for free. So the way to make it cheaper is to stop sending the parts that are not prose.

Gemini receives text, never the file. Before anything is chunked, lib/ingest/clean.ts drops endnotes and bibliographies, running heads and footers, hyphenation across line breaks, ligatures and zero-width junk.

Measured on a real 717,000-character academic PDF: 16% fewer tokens and 8 fewer API calls. And the note shown when you add a source tells you what it skipped — a saving you cannot see is a saving you cannot trust.

Why the threshold is conservative

pdfjs inlines superscript endnote markers, so a sentence can begin “22 Shrewdly, WestExec…” and look bibliographic while being the actual argument. Cutting more aggressively deletes the book.

So the cleaner drops pages that are mostly citation lines, plus runs of three or more consecutive citation lines inside otherwise-prose pages — and stops there. test-formats.mjs specifically checks that the cleaner does not mistake cited prose for a bibliography, because that failure deletes content silently.

Headings are for the chunker, not for you

PDF headings are recovered from font sizes and emitted as Markdown — 156 of them in that same book — and article HTML becomes Markdown rather than flat text. The README is explicit that this is “partly about tokens and mostly about giving the chunker real boundaries, so a chunk is a coherent passage instead of half of two.”

That is the deeper point. A chunk that straddles two sections produces an extraction with muddled context and a citation that points at a page where the claim is only half present. Structure recovered early pays for itself three stages later.

And the other free win: resolution

“Nasser” and “Gamal Abdel Nasser” become one person. Exact matches are free; only genuinely ambiguous pairs reach the model, batched ten at a time. The bias is stated and deliberate: “it would rather leave two entries for one person than fuse two people” — because splitting a merged pair is much harder than merging a split one, and a wrongly fused entity corrupts every sentence that cites it.

Check yourself: what does a born-digital PDF spend on OCR?
Chapter 10

The half you actually live in

Raazi is a reading app first — the user said so — and the reader is the largest file in the repo.

Two pieces of it are worth pulling out, because both are the kind of problem that costs an afternoon and is invisible once solved.

The stacking-context trap

Read the symptom on lines 767–769: “a fixed rail at body level painted over the whole book — the text was all there, full width and correct, with the first seventy pixels of every line hidden behind the navigation.”

The cause is a rule almost nobody has memorised: an element with opacity below 1 creates a stacking context. The page wrapper fades in; that fade makes a stacking context; the reader's z-40 is therefore resolved inside the wrapper and never competes with the rail's z-30 at all.

And note the fix's framing — “moving it to the body ends the argument rather than winning it”. Raising the z-index would have worked until the next transform, filter or containment property appeared somewhere up the tree. A portal is proof against the whole class.

Reading a book aloud, for nothing

The reasoning for using the browser's own voices is the same reasoning as the rest of the app: a book is around half a million characters, which exhausts the monthly free allowance of every hosted TTS service in a sitting or two — and would mean posting the text of everything you read to somebody's server, in an app whose whole premise is a library that lives on your disk.

The cost was three platform bugs, all handled in one module so the reader can treat speech as: say this, tell me when it is genuinely finished.

Check yourself: what goes wrong if you call speechSynthesis.cancel() and treat onend as “finished”?
Chapter 11

Change it yourself

Four exercises, in order of difficulty. Each one uses a different layer of what you have just read.

  1. Change a threshold. COVERAGE_TARGET is 0.85 and EVIDENCE_PER_PASS is 40. Lower the target to 0.6 and watch how many entries stop being flagged as undercovered. This is the fastest way to feel what those two numbers actually trade against each other — passes cost calls, coverage costs passes.
  2. Add a discard reason. lib/discard-reasons.ts is data: a reason, a scope, and the wording carried back into the prompts. Adding one teaches you the block/teach split from Chapter 8 better than reading it does.
  3. Add a provider. Anything speaking the OpenAI API already works through lib/ai/openai.ts. Add it to providers.ts with honest capabilities — and then check test-routing.mjs still passes, because declaring vision you do not have is exactly what rule one exists to catch.
  4. Add a pipeline stage. A new task kind: a handler, a queue entry, a priority band, and a place in the schema for what it writes. Follow lib/pipeline/verify.ts — it is the newest stage and the cleanest example of the whole shape.

Running it

npm run dev

Port 5400. Or double-click Raazi.exe, which starts the server in the background and sits in the tray — closing the browser leaves it running, so a long ingest keeps going.

npm test

150 assertions, no API key needed. test-resume.mjs drives the real worker against a scratch database with injected handlers, including a simulated kill mid-run and a real Gemini quota-error payload — which is how you test a durability guarantee rather than assert it.

Habits that separate professionals from hobbyists

  • Make every unit of work a row. If it is in memory, it does not survive; if it is in a table with an atomic claim, it does.
  • Classify failures before handling them. Six dispositions here, and each one has a different correct response. Retrying everything is a strategy for systems that never run long enough to matter.
  • Default to the cheap mistake. When two guesses cost wildly different amounts, pick the cheap one, not the likely one.
  • Structural checks cannot see semantic failures. Chapter 7 is the general case: 100% coverage, no dead citations, and a sentence sourced from the model's own knowledge.
  • Be exact about what you guarantee. The ledger blocks; the correction teaches. One is a rule, one is a nudge, and saying which is which is what makes the claim worth anything.
  • When you cannot explain it, you do not understand it yet. Try explaining why a bare 429 is treated as a short window. The gaps announce themselves.
